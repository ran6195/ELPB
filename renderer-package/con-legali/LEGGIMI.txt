Backend: https://elpb.edysma.com   |   Pagine legali: locali
==========================================================

AGGIORNARE UN SITO CON UNA VERSIONE PRECEDENTE
  Sostituire via FTP i file PHP nella cartella del renderer: page.php,
  BlockRenderer.php, config.php, thank-you.php, legal-pages.php.
  NON sovrascrivere .env e .htaccess (contengono le impostazioni del sito).

CONTENUTO DEL PACCHETTO
  lp/                     cartella del renderer (il nome si può cambiare)
    .env                  configurazione            -> DA MODIFICARE
    .htaccess             URL puliti e protezioni   -> DA MODIFICARE (RewriteBase)
    page.php              punto d'ingresso della landing page
    BlockRenderer.php     genera l'HTML dei blocchi
    config.php            impostazioni comuni
    legal-pages.php       pagine Privacy / Condizioni / Cookies
    thank-you.php         thank-you statica di ripiego
  menu-legali/            template delle pagine legali
    .htaccess             blocca l'accesso diretto ai template
    LegalTemplateProcessor.php, privacy.php, condizioni.php, cookies.php

  ATTENZIONE: i file .env e .htaccess iniziano con un punto e su macOS/Linux
  sono nascosti. Verificare che vengano caricati.

REQUISITI DEL SERVER
  - PHP 8.0 o superiore, con estensione cURL
  - Connessioni HTTPS in uscita verso elpb.edysma.com
  - Apache con mod_rewrite e AllowOverride attivo (per gli URL puliti)

STRUTTURA SUL SERVER
  Le due cartelle devono stare UNA ACCANTO ALL'ALTRA:

    public_html/
    ├── lp/
    └── menu-legali/

  (legal-pages.php carica ../menu-legali/)

INSTALLAZIONE
  1. Caricare via FTP le cartelle lp/ e menu-legali/ nella radice del sito.
  2. lp/.env -> impostare LEGAL_BASE_URL con il dominio reale,
     es. https://www.miosito.it/lp
  3. lp/.htaccess -> RewriteBase deve corrispondere alla cartella:
       cartella /lp/            -> RewriteBase /lp/   (già impostato)
       altro nome, es. /promo/  -> RewriteBase /promo/ e LEGAL_BASE_URL .../promo
       radice del dominio       -> RewriteBase /  e LEGAL_BASE_URL vuota
                                   (in questo caso menu-legali/ va un livello
                                   SOPRA la radice pubblica)
  4. Permessi: cartelle 755, file 644.
  5. Nel pannello ELPB associare alla landing page il dominio del sito
     (Impostazioni pagina > Domini: obbligatorio per pubblicarla),
     verificare che sia PUBBLICATA e che il Footer Legale abbia i dati
     legali compilati.
  6. Se il form usa reCAPTCHA: aggiungere il dominio del sito alla chiave
     nella console Google reCAPTCHA.

INDIRIZZI RISULTANTI
  Landing page:   https://www.miosito.it/lp/{slug}
  Privacy:        https://www.miosito.it/lp/legal/{slug}/privacy
  Condizioni:     https://www.miosito.it/lp/legal/{slug}/condizioni
  Cookies:        https://www.miosito.it/lp/legal/{slug}/cookies
  Senza mod_rewrite: https://www.miosito.it/lp/page.php?slug={slug}

VERIFICHE DOPO L'INSTALLAZIONE
  [ ] https://elpb.edysma.com/backend/public/api/page/{slug} restituisce JSON
  [ ] la landing page si vede con immagini, font, slider e video
  [ ] https://www.miosito.it/lp/.env risponde 403
  [ ] https://www.miosito.it/menu-legali/privacy.php risponde 403
  [ ] l'invio del form porta alla thank-you e il lead compare nel pannello
  [ ] i link Privacy / Condizioni / Cookies del footer funzionano
  [ ] nel pannello ELPB, Admin > Renderer, il sito compare con
      "Standalone 2.1.1" dopo aver aperto la landing page
  [ ] DEBUG=false in produzione

PROBLEMI COMUNI
  "Pagina non trovata"        pagina non pubblicata o slug errato
  "Si è verificato un errore" cURL assente o connessioni in uscita bloccate
                              (mettere DEBUG=true per vedere il dettaglio)
  Pagina bianca / errore 500  PHP inferiore a 8.0
  404 su ogni URL             RewriteBase errato o mod_rewrite non attivo
  Link legali in 404          LEGAL_BASE_URL non impostata o menu-legali/
                              non accanto alla cartella del renderer
  Sito WordPress/Joomla       tenere il renderer in una sottocartella con il
                              suo .htaccess, così il CMS non intercetta gli URL
